# 英語音読練習PWA 要件定義書

- 作成日: 2026-08-23
- 作成者: millibarjp@gmail.com（ユーザー）との対話に基づきClaude Codeが作成

## 1. 概要

DUO3.0の英文（560件）を教材として、スマートフォンを中心に音読練習（リピーティング／シャドーイング）を行うPWA（Progressive Web App）を開発する。教材データ（英文・日本語訳・音声ファイル）はユーザー自身のGoogleドライブ上に保持し、アプリはそれを読み込んでオフラインでも練習できるようにする。

## 2. 対象ユーザー

- 主利用者: 自分（millibarjp@gmail.com）
- 将来的には家族・友人と共有することを想定する
  - フェーズ1では自分のGoogleアカウントでの動作確認を優先する
  - 各自が自分のGoogleアカウントでログインし、自分のドライブ内教材を参照する形は将来拡張とする（[8.将来拡張](#8-将来拡張フェーズ1のスコープ外) 参照）

## 3. 利用シーン・非機能要件

- 主な利用デバイス: スマートフォン（レスポンシブ対応は必須ではないが、スマホでの使いやすさを優先）
- オフラインでも一通り使えること（Service WorkerによるアプリシェルのキャッシュとIndexedDBによる教材データのキャッシュ）
- UIは日本語
- ホスティング先: GitHub Pages（静的サイトホスティング。サーバーサイド処理は持たない前提）
- コンテンツ（DUO3.0由来の英文テキスト・日本語訳・音声）は私的利用の範囲内で使用し、第三者への再配布は行わない

## 4. コンテンツとデータ管理

### 4.1 コンテンツの単位

- 1件の練習コンテンツ = 1段落（複数文で構成される）
- 全560件（DUO3.0の全セクション分）

### 4.2 データソース

- 英文・日本語訳のテキストデータは、ユーザーのGoogleスプレッドシートで管理されている内容を、Googleドライブ上のTSVファイル等に書き出したものを読み込む（スプレッドシートAPIを直接読むのではなく、Drive上のファイルを読む）
- 音声ファイルはユーザーのGoogleドライブ内のファイルを読み込む
- そのためアプリにはGoogleドライブ連携（OAuth認証・読み取りアクセス）が必要

### 4.3 TSVの列構成（想定）

既存データに準拠し、以下の列を持つ想定（詳細な列名・フォーマットは仕様書フェーズで確定する）:

| 列                         | 内容                                                                         |
| -------------------------- | ---------------------------------------------------------------------------- |
| 通し番号                   | コンテンツの一意なID（1〜560）                                               |
| カテゴリ（セクション番号） | DUO3.0のセクション番号                                                       |
| 英文テキスト               | 練習対象の英文（1段落）                                                      |
| 日本語訳テキスト           | 対応する日本語訳                                                             |
| 音声ファイル名             | 対応する手本音声ファイル名（Googleドライブ上のファイルとファイル名で紐付け） |

### 4.4 オフラインキャッシュ方針

- 初回利用時に560件すべてのテキスト・音声データを一括ダウンロードし、IndexedDB等にキャッシュする（部分キャッシュや遅延ダウンロードは行わない）
- データ更新（スプレッドシート／音声ファイルの変更）への追従は自動同期ではなく、ユーザーが手動で「同期」ボタンを押すことで再取得する

## 5. 機能要件

### 5.0 画面構成・ナビゲーション

初期セットアップ（Driveフォルダ登録）完了後のページ構成は、大きく以下の3つとする。

1. 練習画面（5.3節）
2. 英文選択画面（5.2節）
3. 練習履歴画面（5.4節）

1〜3は画面下部のタブ型ナビゲーションで切り替える。設定画面（5.2.1節）はタブには含めず、英文選択画面右上のボタンから開くサブ画面とする。

アプリ起動時に最初に表示されるのは練習画面とする。英文再生中・待機中は、タブナビゲーション（英文選択／練習履歴タブ）をdisabledとし、他画面へ遷移できないようにする。

### 5.1 認証

- Google OAuthによるログイン（Googleドライブへの読み取りアクセス許可を取得）
- フェーズ1では自分のアカウントでの利用のみを想定

### 5.2 英文選択画面

コンテンツの練習回数を参考に、練習する英文（出題範囲）を選択する画面。

- 560件のコンテンツをカードで一覧表示する
- 各英文カードに表示する情報:
  - 英文の通し番号
  - 英文テキスト
  - リピーティングモードでの練習回数・シャドーイングモードでの練習回数（それぞれ区別）
  - 「お気に入り」登録・解除ボタン
  - 練習対象チェックボックス（チェックを入れた英文が、練習画面での出題範囲になる）
    - 初期状態（初回同期直後）は全件チェックON
    - 選択状態はアプリを再起動しても保持する（ローカルに保存）
- カテゴリ（セクション番号）ごとに見出しを設け、各英文カードはそのカテゴリの配下に表示する
  - カテゴリ見出しに、そのカテゴリ内の英文を一括で全選択／全解除できるチェックボックスを設ける
- フィルター機能（表示の絞り込み。出題範囲＝練習対象チェックボックスの状態そのものは変えない）
  - カテゴリ絞り込み: ドロップダウンで1つだけ選ぶ方式ではなく、カテゴリごとのチェックボックスで表示ON/OFFを切り替えられる（複数カテゴリを同時に表示可能）
- 画面右上に設定ボタンを配置し、設定画面（5.2.1節）を開く

#### 5.2.1 設定画面

英文選択画面右上の設定ボタンから開くサブ画面（タブナビゲーションには含めない）。

- Google DriveフォルダIDの入力欄
- 保存ボタン
- 同期ボタン
- 閉じるボタン（英文選択画面に戻る）

### 5.3 練習画面

アプリ起動時に最初に表示される画面。英文選択画面で選択した出題範囲のうち、現在の英文を表示する。

- 表示するもの: 英文、日本語訳（手本音声の再生と合わせて画面に表示）
  - 英文・日本語訳はそれぞれ独立にON/OFF切り替え可能（例: 日本語訳だけ隠して英文のみ表示、なども可能）
  - 現在の英文の通し番号・カテゴリ
  - 出題範囲内の総数と現在のインデックス（例: 「1/560」のような表示）
  - 連続学習日数（ストリーク。アプリ全体で1つの値を、練習履歴画面5.4節と共通で表示する）
- 手本音声（Googleドライブから取得した音声ファイル）を再生する
- 練習モードとして以下の2種類を用意し、ユーザーが選択できる
  - **リピーティングモード**: 手本音声の再生後、その音声と同じ長さだけ待機する（その間にユーザーが声に出して練習する）。待機後、自動的に次のコンテンツへ進む
  - **シャドーイングモード**: 手本音声の再生後、待機せず自動的に次のコンテンツへ進む
- お気に入りのみ表示チェックボックス
- 各コンテンツを「お気に入り」に登録・解除できる
- 再生速度は等速のみ（速度調整機能は今回のスコープ外）
- 録音・自動採点機能は持たない（[8.将来拡張](#8-将来拡張フェーズ1のスコープ外) 参照）

#### 5.3.1 再生コントロール

- 再生ボタン: 手本音声を再生する
- 停止ボタン: 再生中の音声を停止する（リピーティングモードの待機中も停止できる）
- 次へボタン: 次のコンテンツへ手動で進む（自動遷移を待たずに進める）
- 前へボタン: 前のコンテンツへ戻る
- プログレスバー: 以下の2つの状態を視覚的に表現する
  - 手本音声の再生中: 再生の進行度（音声の何%再生済みか）
  - リピーティングモードの待機（ポーズ）中: 待機時間の残り（経過度）
  - 両者は連続した1本のバー上で表現し、いま「再生中」か「待機中」かが視覚的に区別できるようにする（詳細な見た目は仕様書フェーズで検討）

#### 5.3.2 出題順序モード

練習範囲内（英文選択画面5.2節で選択した「練習対象」チェックボックス、および「お気に入りのみ表示」ONの場合はその絞り込みを反映した結果）のコンテンツをどの順序・回数で再生するかを、以下の2つの独立したON/OFFスイッチで制御する（3択の排他選択ではない）。5.3節の「リピーティングモード／シャドーイングモード」（待機時間の有無）とはさらに独立した設定であり、これら2つのスイッチと組み合わせて使用する。

- **ランダム再生スイッチ**:
  - OFF（既定）: 次に進むコンテンツは通し番号順（**順次再生**）
  - ON: 次に進むコンテンツは出題範囲内からランダムに選出する（**ランダム再生**）
- **1リピート再生スイッチ**:
  - OFF（既定）: 手本音声の再生後（リピーティングモードなら待機後）、自動的に次のコンテンツへ進む。「次のコンテンツ」がどれかは、ランダム再生スイッチのON/OFFに従う
  - ON（**1リピート再生**）: ユーザーが次へ／前へボタンを押さない限り、同じコンテンツを繰り返し再生し続ける（自動ではインデックスが進まない）
    - 手本音声の再生が終わったら、リピーティングモードの場合はその音声の長さ分待機してから、シャドーイングモードの場合は待機せず（0秒）、同じコンテンツを再度再生する（これを繰り返す）

**次へ／前へボタンの挙動**（ランダム再生・1リピート再生のON/OFFいずれの組み合わせでも共通のルール）:

- **停止ボタン**: 再生（および待機）を停止する
- **次へボタン**:
  - 再生中（または待機中）の場合: 直ちに次のコンテンツ（ランダム再生ONならランダム選出、OFFなら通し番号で次）の再生を開始する
  - 停止中の場合: 次のコンテンツにインデックスだけ進める（自動再生はしない。再生ボタンを押すまで再生されない）
- **前へボタン**: 次へボタンと同様の挙動を、1つ前（またはランダム再生ONの場合は直前に再生したコンテンツ）に対して行う

> 実装イメージ（参考）: 1リピート再生スイッチがONのときはインデックスを更新しない。OFFのときは、再生後の待機（リピーティング＝音声の長さ／シャドーイング＝0秒）を経て自動的にインデックスを更新する（ランダム再生スイッチがOFFならインクリメント、ONならランダム選出）。次へ／前へボタンは、1リピート再生のON/OFFに関わらず、このインデックス更新ロジック（ランダム再生スイッチに従う）を手動で発火させる操作として扱う。

### 5.4 練習履歴画面

学習状況を振り返るための画面。

- 連続学習日数（ストリーク。5.3節の練習画面と共通の値）
- 直近7日間の棒グラフ: 日ごとのリピーティング・シャドーイングそれぞれの練習回数を表示する
- 直近196日間（7×28マス）の練習頻度グリッド: GitHubのコントリビューショングラフのように、1マス＝1日とし、その日の練習回数に応じてマスの色の濃淡を変える
- 全英文（560マス）の練習頻度グリッド: 1マス＝1コンテンツ（英文）とし、そのコンテンツの練習回数（リピーティング・シャドーイングの合計）に応じてマスの色の濃淡を変える（練習回数が多いほど濃い色）

### 5.5 学習履歴・進捗管理

記録する情報:

- コンテンツ（文）ごとの練習回数（リピーティングモードでの練習回数とシャドーイングモードでの練習回数を区別して記録する）
- コンテンツごとの最終練習日
- 日ごとの練習回数（練習履歴画面5.4節の日別グラフ・グリッド用に、モード別に記録する）
- アプリ全体での連続学習日数（何か1件でも練習した日をカウント）
- コンテンツごとのお気に入り登録状態

これらの情報は、英文選択画面（5.2節）・練習履歴画面（5.4節）での絞り込み・可視化に利用する。

保存先はIndexedDB（ブラウザのローカルストレージ）とする。Googleドライブへのバックアップは将来拡張とする（[8.将来拡張](#8-将来拡張フェーズ1のスコープ外) 参照）。

### 5.6 練習状態の保存・復元

- 練習を中断してアプリを閉じ、再度開いたときに、直前の練習状態を復元できるようにする
- 保存対象:
  - 練習モード（リピーティングモード or シャドーイングモード）
  - 出題順序モード（ランダム再生スイッチ・1リピート再生スイッチのON/OFF状態）
  - 練習対象として選択中の英文ID一覧（5.2節の練習対象チェックボックスの状態）
  - お気に入りのみ表示のON/OFF状態
  - 出題中（再生中）のコンテンツ
- これらは端末・セッションに紐づく一時的な状態であるため、IndexedDBではなく`localStorage`に保存する（学習履歴・教材キャッシュとは保存先を分ける）

### 5.7 データ同期

- 「同期」ボタンにより、Googleドライブ上のTSV・音声ファイルを再取得し、ローカルキャッシュ（IndexedDB）を更新できる

## 6. PWA要件

- インストール可能（ホーム画面への追加）
- オフラインで一通りの機能（コンテンツ閲覧・音声再生・練習・履歴確認）が利用できる
- Service Workerによるアプリシェルのキャッシュ
- IndexedDB等による教材データ（テキスト・音声）・学習履歴のローカル永続化

## 7. 技術的な前提・制約

- ホスティング: GitHub Pages（静的サイト。サーバーサイドロジックは持たない）
- Googleドライブ連携: クライアントサイドでのGoogle OAuth（Google Identity Services等）を用いる想定。詳細な認証方式・スコープは仕様書フェーズで確定する
- 学習履歴・教材キャッシュの保存先はIndexedDB、練習中の一時的な状態（5.6節）の保存先は`localStorage`とし、サーバー側でのデータ永続化は行わない（複数デバイス間の同期は今回のスコープ外）

## 8. 将来拡張（フェーズ1のスコープ外）

以下は今回の要件定義・実装の対象外とし、将来のバージョンで検討する:

- 音声認識を用いた発音・音読の自動採点とフィードバック
- ユーザー自身の音読の録音・再生（手本音声との聞き比べ）
- 複数ユーザーが各自のGoogleアカウントでログインし、それぞれのドライブ内教材を利用する本格的なマルチユーザー対応
- 音声の再生速度調整（スロー再生等）
- 練習履歴に基づく自動レコメンド（忘却曲線等を用いた出題順の自動選択）
- 学習履歴（練習回数・最終練習日・お気に入り等）のGoogleドライブへのバックアップ・復元機能

## 9. 今後（仕様書フェーズ）で確定させる事項

- TSVファイルの正確なフォーマット（区切り文字、エンコーディング、実際の列名・順序）
- GoogleドライブAPIの認証方式・必要スコープ（drive.readonly等）の詳細
- TSVファイル・音声ファイルの格納場所（フォルダ構成）とアプリからの参照方法（ファイルID指定 or ファイル名検索）
- 560件・音声ファイル込みの概算データ容量、および一括ダウンロード時のUX（進捗表示、失敗時のリトライ等）
- GitHub Pagesにおけるリポジトリ名・公開パス（PWAのscope/base pathへの影響）
- IndexedDBのスキーマ設計（コンテンツテーブル、練習履歴テーブル等）
- `localStorage`に保存する練習状態のデータ構造
