# 英語音読練習PWA テスト計画書

- 作成日: 2026-08-23
- 前提: [docs/requirements.md](./requirements.md)、[docs/spec.md](./spec.md)、[docs/implementation-plan.md](./implementation-plan.md)

## 1. テスト方針

- **単体テスト（Vitest）**: `src/domain/`のドメインロジック、`src/data/`のラッパー層を対象に、React非依存の純粋なロジックを重点的に検証する。実装計画書のWP1・WP2に対応し、原則としてテストコードを先に用意してから実装する
- **コンポーネントテスト（Vitest + Testing Library）**: 個々のUI部品・画面の表示分岐やユーザー操作を検証する。実装計画書WP3に対応
- **E2Eテスト（Playwright）**: 画面をまたぐ一連の練習フローを検証する。Google Drive/GIS関連の外部通信はモック化し、CIで自動実行できるようにする
- **手動テスト**: 実際のGoogleアカウントでのOAuth同意画面、実データでの`.opus`再生、スマートフォン実機での操作性など、自動化が難しい／実データ依存の項目は手動確認とする

## 2. テスト環境・モック方針

| 対象                             | モック／テスト手法                                                                                                                                                                                                               |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IndexedDB                        | `fake-indexeddb`をVitestのセットアップで注入し、実ブラウザなしでテストする                                                                                                                                                       |
| `localStorage`                   | Vitestの実行環境（jsdom）標準の`localStorage`を使用                                                                                                                                                                              |
| Google Identity Services（認証） | `google.accounts.oauth2`をモックオブジェクトに差し替え、固定のアクセストークンを返す                                                                                                                                             |
| Google Drive API                 | 単体テストでは`fetch`をモックし、固定のレスポンス（ファイル一覧・TSV内容・音声バイナリ）を返す。E2Eテストでは、Playwrightのネットワークインターセプト（`page.route`）でDrive APIエンドポイントをテスト用フィクスチャに差し替える |
| 音声再生                         | 単体・コンポーネントテストでは`HTMLMediaElement`の`play`/`pause`等をモック化する（jsdomは実際の音声再生非対応のため）。E2Eテストは実ブラウザ（Chromium）上で、テスト用の短い音声ファイルを実際に再生して検証する                 |
| 日付・時刻                       | ストリーク計算等、日付に依存するロジックは、テスト対象関数に「現在日時」を引数として注入できる設計にし（`Date.now()`を直接呼ばない）、テストから任意の日時を指定できるようにする                                                 |

## 3. テストデータ・フィクスチャ

`tests/fixtures/`に以下を用意する。

- `sample.tsv`: 数件〜十数件程度のサンプルコンテンツ（正常系）。ヘッダー行、複数カテゴリ、日本語訳に改行やタブを含まない典型データ
- `sample-invalid.tsv`: 列数不足の行、空行、空のセルなどを含む異常系データ
- `sample-audio.opus` / `sample-audio.mp3`: 1〜2秒程度の短い音声ファイル（プログレスバー・待機時間・自動遷移の検証に使用）
- Drive APIレスポンスのJSONフィクスチャ（`files.list`のレスポンス例、ルート直下のみ／サブフォルダありの2パターン）

## 4. 単体テストケース（Vitest）

### 4.1 `domain/tsv.ts`（TSVパーサー）

- 正常なTSV（ヘッダー行＋複数行）を`Content[]`に正しく変換できる
- 空行はスキップされる
- 列数が不足する行はエラーとして扱われる（該当行番号を含むエラー情報を返す）
- `id`列が数値に変換できない場合はエラーになる
- 同一`id`が重複する場合の挙動（後勝ち／エラーのいずれかを決定し、その通りに動作する）

### 4.2 `domain/playback`（再生状態遷移・進行ロジック）

`practiceMode`（repeating/shadowing）× `isRandom`（true/false）× `isRepeatOne`（true/false）の組み合わせ（8パターン）を軸に検証する。

- `stopped`から再生ボタンで`playing`に遷移する
- `playing`で音声再生終了後:
  - `practiceMode='shadowing'`の場合、待機せず進行ロジックが実行される
  - `practiceMode='repeating'`の場合、`waiting`に遷移し、待機時間経過後に進行ロジックが実行される
- 進行ロジック（8.2節）:
  - `isRepeatOne=true`: インデックスが変化せず、同じコンテンツで`playing`に戻る
  - `isRepeatOne=false, isRandom=false`: 通し番号で次のインデックスに進む（末尾では先頭に戻る）
  - `isRepeatOne=false, isRandom=true`: 出題範囲内からランダムに選出される（直前と同一コンテンツが連続で選ばれない）。乱数生成器を差し替え可能にし、決定的にテストする
- 次へ／前へボタン（8.3節）:
  - `playing`/`waiting`中に押すと、即座に次／前のコンテンツに切り替わり`playing`になる
  - `stopped`中に押すと、インデックスのみ変わり`stopped`のままになる
  - `isRandom=true`のとき、「次へ」は新規ランダム選出、「前へ」は`shuffledHistory`を1つ戻る。履歴がない場合は「前へ」が無効化される
- 停止ボタン: `playing`/`waiting`いずれからも`stopped`に遷移し、タイマー・再生が確実に止まる
- プログレスバー計算（8.4節）:
  - `playing`中: `currentTime / duration`が0〜1の範囲で正しく計算される
  - `waiting`中: 経過時間 / 待機時間（＝直前音声の`duration`）が正しく計算される
  - `stopped`中は0を返す

### 4.3 `domain/streak.ts`（連続学習日数）

- 練習日が1日も無い場合は0
- 今日を含めて連続N日練習している場合、Nを返す
- 今日はまだ練習していないが昨日までM日連続の場合、Mを返す（要件定義書9.2節の仕様）
- 練習日の間に空白日がある場合、そこで連続がリセットされる（直近の連続区間のみを見る）
- 日付またぎ・タイムゾーンの境界値（日付の切り替わり直後等）

### 4.4 `domain/grid.ts`（頻度グリッドの色区分）

- 練習回数（`repeatingCount + shadowingCount`）ごとに、定義した閾値通りの区分（色レベル）が返る
- 境界値（各閾値のちょうど境目の回数）で正しい区分になる
- 0回のコンテンツが正しく「無色」区分になる

### 4.5 `data/db.ts`（IndexedDBラッパー）

- `contents`ストアへのアップサート・全件取得・IDでの取得
- `practiceRecords`ストアの作成・`repeatingCount`/`shadowingCount`の更新・お気に入りフラグの更新
- `dailyLogs`ストアの`incrementDailyLog`: 初回呼び出しで該当モードのカウントが1になる、同日に複数回呼んでもレコードは1件のまま各モードのカウントが積み上がる、`repeatingCount`/`shadowingCount`は独立してカウントされる
- `audioBlobs`ストアへの保存・取得・存在チェック
- DBスキーマのマイグレーション（バージョン初期化）が正しく行われる（開発中は後方互換を持たせない方針。仕様書5.2節）

### 4.6 `data/localStorage.ts`（localStorageラッパー）

- `PracticeSessionState`の保存・復元（往復でオブジェクトが一致する）
- `SelectionState`（`selectedContentIds`・`favoritesOnly`）の保存・復元（往復でオブジェクトが一致する）
- `DriveSettings`の保存・復元
- 値が存在しない場合に`null`（または既定値）を返す
- 不正なJSON（壊れたデータ）が入っていた場合にクラッシュせず既定値にフォールバックする

### 4.7 `data/driveClient.ts`（Drive連携）

- ルート直下のみにTSV・音声がある場合に正しくファイルを解決できる（`fetch`モック）
- 直下サブフォルダに音声がある場合も、1階層再帰探索でファイルを解決できる
- TSVの`audioFileName`と一致するファイルが見つからない場合、該当コンテンツをエラー扱いとして記録し、処理全体は継続する
- 拡張子ごとのMIMEタイプ判定（7.3節の対応表通り）
- 認証エラー（401等）発生時に、上位へエラーとして通知される

### 4.8 `domain/sync.ts`（同期処理）

- 全件成功時、進捗コールバックが0%→100%まで正しく呼ばれる
- 一部ファイルの取得に失敗した場合、失敗をスキップして残りを継続し、最終的に失敗件数を返す
- TSV自体の取得・パースに失敗した場合は、同期処理全体を中断しエラーを返す

### 4.9 `domain/selection.ts`（出題範囲の算出、仕様書8.0節）

- 全コンテンツが選択済み・お気に入りのみ表示OFFの場合、id昇順で全件を返す
- 一部のみ選択されている場合、選択された分のみid昇順で返す（選択順ではない）
- お気に入りのみ表示ONの場合、「選択済み ∩ お気に入り」のみに絞り込まれる
- 選択が0件、またはお気に入りのみ表示ONでお気に入りが1件も無い場合は空配列を返す
- 存在しないコンテンツIDが`selectedContentIds`に含まれていても無視される

### 4.10 `domain/dailyGrid.ts`（日別頻度シリーズの算出、仕様書9.4節）

- 直近7日分・直近196日分など、指定した日数分の配列を古い日付→新しい日付の順で返す
- 該当日の`DailyLog`が無い日は`repeatingCount`/`shadowingCount`とも0件として埋められる
- 指定期間の範囲外の`DailyLog`は結果に含まれない
- 基準日（今日）が最後の要素として含まれる
- 入力の`DailyLog`が日付順でなくても正しく処理される

## 5. コンポーネントテストケース（Testing Library）

- `ProgressBar`: `playing`/`waiting`/`stopped`それぞれの状態で見た目（進捗値・スタイル区分）が切り替わる
- `FrequencyGrid`: 560件分のデータを渡した際、各マスの色区分がデータ通りに反映される
- `PlaybackControls`: 各ボタン押下で対応するコールバックが呼ばれる。状態（`playing`/`stopped`等）に応じてボタンの活性・非活性が正しく切り替わる
- `ContentText`: 英文・日本語訳のON/OFFがそれぞれ独立して表示・非表示を切り替えられる
- `ContentSelectionScreen`（旧`ContentListScreen`。参照: docs/spec.md 4.2節）: カテゴリごとに見出し・英文カードが表示される。練習対象チェックボックスが`selectedContentIds`を反映し、操作でコールバックが呼ばれる。カテゴリ見出しの全選択／全解除チェックボックス（全選択済み／未選択／一部選択済み＝indeterminateの3状態）が正しく表示・動作する。カテゴリ絞り込みで表示件数が変化する。お気に入りボタンでトグルできる
- `SetupScreen`: フォルダID未入力時は次に進めない、入力後は`localStorage`に保存され次画面に遷移する
- `SettingsScreen`（参照: docs/spec.md 4.2.1節）: フォルダID保存・同期ボタン・`syncError`表示・閉じるボタンが動作する
- `PracticeScreen`（参照: docs/spec.md 4.1節）: モード切り替えUI（練習モード／ランダム再生スイッチ／1リピート再生スイッチ）の操作で内部状態が切り替わる。通し番号・カテゴリ・「現在のインデックス/総数」・連続学習日数が表示される。お気に入りのみ表示チェックボックスの操作で`onChangeFavoritesOnly`が呼ばれる

## 9. CI実行方針

- Pull Request作成時にGitHub Actionsで以下を自動実行する:
  - Lint（ESLint）
  - 単体・コンポーネントテスト（Vitest）
  - ビルド（`vite build`）
  - E2Eテスト（Playwright、モック環境）
- すべて成功していることを、`main`へのマージ承認をユーザーに依頼する際の前提条件とする（実装計画書1章のルール）
